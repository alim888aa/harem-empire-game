## Reproduction and scoped change
`PalaceScene` derives measured movement speed from accepted x/z displacement over delta time, after movement/collision. Previously `characterModels` selected Run above the single midpoint and Walk below it. A new public-model-interface regression alternated prince measured speeds 2.45 and 2.55 around its 2.5 midpoint. **Before the repair** the test failed: the clip flipped from Walk to Run on the next update, invoking `change()` and resetting/crossfading repeatedly. This is a deterministic source-level seam defect, not proof that it is the sole cause of the human's visible vibration.

The repair uses distinct entry/exit thresholds, retaining the current gait when measured speed jitters near the midpoint. Landing and grounded movement use the same decision; outfit replacement preserves gait history. Controller speeds, spatial movement, collision rules, animations, campaign RNG and save schema are unchanged. Ordinary full-speed walk/run remains selectable. The new regression covers seam oscillation from both Walk and Run and crossing to the other gait. The source file stays below the repository size guard.
